# Research agent pack — v2 (flight-risk)

**What changed from v1:** (1) no top-level `output/` — every round gets its own folder `rounds/round-NN-<slug>/` holding the work order, ALL of that round's outputs, and a `ROUND_NN_FINDINGS.md` written for a coauthor with zero context (plain-language narrative, toddler-level method glosses, traced numbers only, the complete list of scripts touched, and a **Suggested next steps** section); (2) the auto-drafted next-round file is gone — next steps live in the findings, and `/plan-round` (or `auto N` chaining) drafts the next round FROM them, so the human can edit the plan between runs; (3) a `human-readable/` dashboard: `PRESENTATION.md` (human-owned deck skeleton naming key artifacts), `MIN_SCRIPTS.md` (generated by `code/sync_min_scripts.py`: the minimum scripts to rebuild those artifacts), `PROJECT_STATE.md` (director-maintained, written for an undergrad RA); (4) a `sync-min-scripts` skill (`.claude/skills/`) that regenerates and verifies MIN_SCRIPTS.md whenever PRESENTATION.md changes; (5) WRDS machinery replaced by OpenSky/pyopensky credentials for this project.

Drop-in scaffolding for an autonomous empirical-finance pipeline: an implementer/reviewer/director/author agent quartet, unattended orchestration, a stop-gate hook, a watchdog, and the integrity machinery (gates, validator, generated run log) that keeps an 8-hour unattended run honest. New here? Read **SETUP_GUIDE.md** — a step-by-step walkthrough for a first-time user or RA.

## One-time per machine

1. Open any pack workspace in its dev container once (this creates the two shared Docker volumes: `claude-config`, `research-secrets`).
2. In the container terminal, log in to the CLI once: `claude` (credentials persist in the volume across rebuilds and across projects).
3. Store secrets in the persisted volume — they are picked up by every future workspace on this machine, so runs are never prompted:

```bash
cat > ~/.secrets/pyopensky_settings.conf <<'CONF'
[default]
username = YOUR_OPENSKY_USERNAME
password = YOUR_OPENSKY_PASSWORD
CONF
echo 'your-ntfy-topic' > ~/.secrets/ntfy_topic
```

`postCreateCommand` installs `~/.secrets/pyopensky_settings.conf` to `~/.config/pyopensky/settings.conf` (mode 600) on every container build; `pyopensky` reads it automatically for Trino access. Credentials are deliberately NOT in this repo: the pack gets copied into many repos and possibly shared for replication someday. Note the design intent regardless: **unattended runs never query OpenSky live** — the human (or an attended session) pulls extracts into `data/raw/opensky/`, and agents read those. A repo-root `.ntfy_topic` file overrides the volume topic per-project if you want separate channels.

## Per project

1. Unzip into an empty directory (note the dotfiles: `.claude/`, `.devcontainer/`, `.gitignore`), then `git init && git add -A && git commit -m "pack"`.
2. Fill in **PROJECT.md**. This is the highest-leverage 30 minutes: it bounds the director's autonomy (identification menu, phasing, decision defaults, exploration stance) and briefs the econometrician (pitfalls). Vague brief → vague rounds.
3. Reopen in the container. Put vendor files in `data/raw/`.
4. `/plan-round` — the director creates `rounds/round-1-<slug>/` and drafts `ROUND_01.md` inside it (at kickoff: data foundations only, no headline regressions before the panel passes its gates). Skim it if you like; it's built to be runnable as-is. Between later runs, edit the latest FINDINGS' Suggested next steps first if you want to steer — that section is what /plan-round reads.

## Launch checklist (before leaving)

```bash
./launch.sh overnight 3          # arms the flag, starts the watchdog, runs /overnight 3 headless
```

or, if you want to drive from the VS Code panel instead of headless:

```bash
./launch.sh arm                  # flag + watchdog live immediately
```

then type `/overnight 3` in the panel. Either way the gate flag is created by the shell, not by the model, so there is nothing to wait for. `./launch.sh status` shows flag/watchdog/STATUS.md state; `./launch.sh disarm` stops a run cleanly.

(or `/run-analysis rounds/ROUND_01.md auto 3` for the analysis loop alone, with no writing closeout)

`/overnight N` wraps the whole night: preflight (snapshot commit, validator check), planning if no round is pending, the `auto N` analysis campaign, then a closeout — scoped lit scan (skipped gracefully if web is denied), `/write-up both`, a numbers-free MORNING_BRIEF.md, and an ntfy ping. `/overnight 0` reruns only the closeout. Underneath it, `auto N` chains up to N rounds: after each round closes (run log → validator → director close-out: ROUND_NN_FINDINGS.md, PROJECT_STATE.md refresh, sync_min_scripts.py → overseer OVERALL verdict with the findings-audit), the director drafts the next round FROM the findings' Suggested next steps; the orchestrator keeps going unless the director marks NEEDS-HUMAN or N is exhausted. Default (no `auto`) runs one round, writes the findings, and stops — no next round file is drafted, so you can edit the Suggested next steps before /plan-round turns them into one. Completion: `ALL COMPLETE` in STATUS.md → stop hook lifts `.remediation_active` → ntfy ping → watchdog exits.

## Design notes

- **Stop gate ↔ watchdog.** The hook blocks at most 2 premature stops per flag lifetime (in-session nudges), then yields to the watchdog as the outer retry loop — so a confused session can't spin, and a rate-limited one still resumes.
- **Flag ownership moved to the shell (v2).** `.remediation_active` is created by `launch.sh` (or `bash watchdog.sh arm`), not by the model; `/overnight` and `/run-analysis` touch it idempotently as their first action as belt-and-braces. The watchdog waits up to 60 min for the flag rather than exiting if it starts first, and its resume prompt is phase-aware (planning vs analysis loop), falling back to re-issuing the recorded `.run_command` when no conversation exists yet.
- **Validator is directory-wide** (`rounds/round-*/**/*.csv`, quarantine excluded) and encodes gates G1–G5 plus the transcription check (reported p vs |coef/se|-implied p). It exits 1 on FAIL; WARNs are for the overseer's judgment.
- **Director integrity.** Every commissioned task is labeled EXPLORE or CONFIRM; CONFIRM requires ex-ante rationale, EXPLORE families report every cell. Judgment calls outside PROJECT.md become DECISION-PENDING memos in DECISIONS.md — the run never stops to ask, it takes the conservative default. This is what keeps an autonomous direction-setter from quietly p-hacking by choice-of-next-analysis, and it doubles as your referee-facing audit trail.
- **WebFetch/WebSearch are denied** in settings.json: an unattended agent reading arbitrary web content is a prompt-injection surface, and the analysis pipeline needs only local data in data/raw/ (package installs go through Bash/pip and are unaffected). The one thing that legitimately needs the web is the author's `/lit-review` — run it attended, with the two deny lines temporarily removed, then restore them (the command reminds you).
- **Seminar-first methods** (STANDING_RULES.md rule 12). The default toolkit is raw-data plots and means, OLS/FE, canonical DiD with event-study figures, and simple IV — evidence a discussant can verify on a napkin. Fancier estimators require a written commission in the round file and always run alongside the simple benchmark; the overseer FAILs "complexity without cause". This is deliberate: a seminar audience is persuaded by transparent designs, not estimator menus.
- **The author never invents numbers or citations.** Tables/figures in paper/ and slides/ are generated by code from output CSVs (`spec_to_tex.py`); every bib entry must have been actually retrieved and read (web), or it sits in LIT_NOTES.md flagged UNVERIFIED. Results with open integrity flags stay out of the draft.
- **The deny list is a guardrail, not a sandbox.** `rm -rf`, `rm -fr`, `rm -r`, `git push`, `git reset --hard`, `git clean`, `sudo` are denied, but string-matching can't cover every permutation. The real protection is: container isolation, no push rights, `data/raw/` gitignored and never touched, commit-per-task, and off-machine backups of `data/raw/`.
- **OpenSky ban-proofing.** OPENSKY_TRINO_RULES.md (T1–T9) is folded into STANDING_RULES; `code/opensky_query.py` is the single door to Trino and refuses SQL without a partition predicate, over-wide partition spans, or unbounded state-vector pulls, runs one query at a time with backoff, caches every result, skips OpenSky's lost-data periods, and logs every SQL to `logs/opensky_queries.log`; `code/98_check_trino_usage.py` fails a round if any script imports pyopensky/trino directly or the guard constants were touched; the `trino` CLI is on the deny list; unattended runs never query live.
- **Human-readable layer.** PRESENTATION.md is the one file agents treat as read-only human editorial direction; MIN_SCRIPTS.md is generated-only (`code/sync_min_scripts.py`, or the sync-min-scripts skill which also resolves the tracer's UNRESOLVED/AMBIGUOUS flags); PROJECT_STATE.md is rewritten by the director each round in deliberately non-PhD language — if it reads like an abstract, the overseer's findings-audit flags it.
- **Customize per project:** PROJECT.md always; round-specific gates in each round file; pyproject deps; STALE_MINUTES/MAX_NUDGES in watchdog.sh if your data pulls run long.
