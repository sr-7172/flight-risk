# ROUND_NN_FINDINGS.md contract (written by the director at round close)

Audience: **a coauthor who has no idea what is going on** — assume they
have not read PROJECT.md, do not remember the last round, and need the
empirical methods explained at toddler level ("we compare each flight's
time to what's normal for that route in that month; if it stays long for
months and only for some countries' airlines, we flag it"). Jargon gets a
one-line gloss on first use. Required sections, in order:

1. **What we were trying to find out this round, and why** — the question
   in plain words and how it fits the paper.
2. **What we did** — each task in one or two sentences, methods explained
   as above.
3. **What we found** — the honest narrative, nulls and failures included.
   Every number cited is transcribed from a CSV in this folder and traced
   inline as `(file.csv, row/spec)`; no number appears without a trace
   (standing rule 5 applies — re-open the CSV, do not quote prose).
4. **Complete list of code scripts created or edited for this round** —
   path + one line on what it does; must reconcile with the round's git
   commits (the overseer diffs this list against `git log` for the round).
5. **Open problems and flags** — BLOCKED items, DEGENERATE-INFERENCE etc.,
   verbatim from STATUS.md/REVIEW_REPORT.md.
6. **Suggested next steps** — a prioritized sketch (5–10 bullets) precise
   enough to seed the next round file: what to run, on what data, and what
   would count as success/failure. This section REPLACES the old
   auto-drafted next-round file; /plan-round reads it (plus any human
   edits to it) as the primary input when the human asks for the next
   round to be drafted.
